# 部署与接入

## 交付边界

本包包含上下文读取、KL 系数和学习率候选网格、UCB、KL 预算惩罚、优化器学习率 hook、状态保存和 CPU 测试。PCPO 主循环仍需要队友把建议参数写回 loss 和验证流程。

## 1. 安装和 CPU 验证

```bash
python -m pip install -r requirements.txt
PYTHONPATH=. python -B -m unittest discover -s tests -v
PYTHONPATH=. python -B examples/cpu_smoke.py
```

## 2. 初始化和上下文

```python
from bo_tuner import PCPOParameterBO
from bo_tuner.integration import apply_learning_rate, context_from_metrics, selected_kl_coefficient

tuner = PCPOParameterBO(seed=42, kl_budget=0.05)
context = context_from_metrics(metrics)
choice = tuner.suggest(context)
apply_learning_rate(optimizer, choice["learning_rate"])
current_beta = selected_kl_coefficient(choice)
```

PCPO loss 中的 KL 项使用 `current_beta`。建议每 10 或 20 轮调用一次 `suggest`，中间保持参数不变。

## 3. 两个 PCPO hook

```python
# hook 1: 在 PCPO loss 中把固定 beta 替换为 current_beta
loss = policy_loss + current_beta * kl_loss

# hook 2: 固定验证窗口结束后
tuner.observe(validation_delta, actual_kl)
```

`validation_delta` 必须来自留出验证集，不能来自最终测试集，也不能直接用训练 reward 代替。参数状态必须与 PCPO checkpoint 使用相同 epoch。

## 4. 试跑和正式训练

先用 21 轮试跑确认 4 次 warmup 后发生一次 UCB 参数选择。正式实验另开运行目录，记录每段的 beta、learning rate、validation_delta 和 actual_kl。

```bash
export PCPO_TARGET_EPOCHS=21
export PCPO_RUN_ROOT=/path/to/runs/pcpo_parameter_bo_seed42
bash /path/to/pcpo/jobs/run_task.sh ocr "$GPU_ID" 1
```

## 5. 验收

固定 PCPO、手工固定参数、无 KL 约束 BO 和带 KL 预算 BO 必须使用相同 seed、图片预算、验证预算和最终测试集。
