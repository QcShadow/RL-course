# 部署与接入

## 交付边界

本包包含独立提示特征、固定总预算约束、4 到 12 张的图片数量分配、变长行号展开、乱序 reward 归组、GP 选点、状态保存和 CPU 测试。队友必须改 DataLoader 和 PCPO 分组统计，不能套用固定 8×8 入口。

## 1. 安装和 CPU 验证

```bash
python -m pip install -r requirements.txt
PYTHONPATH=. python -B -m unittest discover -s tests -v
PYTHONPATH=. python -B examples/cpu_smoke.py
```

## 2. 初始化和变长采样

```python
from integration.features import encode_rows
from bo_budget import BudgetAllocator

features = encode_rows([{"prompt": text} for text in train_dataset.prompts])
allocator = BudgetAllocator(features, seed=42, total_images=64)
batch = allocator.next_batch()
expanded_indices = expand_prompt_indices(batch["prompt_indices"], batch["image_counts"])
train_sampler.set_indices(expanded_indices)
```

## 3. 两个 PCPO hook

```python
# reward gather 后：按真实 Dataset 行号分组
groups = group_flat_rewards(dataset_indices, ocr_rewards,
                            batch["prompt_indices"], batch["image_counts"])
allocator.observe(batch["prompt_indices"], groups)

# PCPO 优势统计：每个提示使用自己的 image_counts，不能 reshape(8, 8)
```

需要队友把 sampler/DataLoader 改成接受变长重复次数，并让优势统计器按变长组计算。总图数仍必须为 64；如果训练 batch 或梯度累积不能整除，先调整 PCPO 配置后再运行。

## 4. 试跑和正式训练

先用 21 轮确认变长组的 reward、优势和 optimizer batch 都正常，再另开 250 轮目录。

```bash
export PCPO_TARGET_EPOCHS=21
export PCPO_RUN_ROOT=/path/to/runs/image_budget_bo_seed42
bash /path/to/pcpo/jobs/run_task.sh ocr "$GPU_ID" 1
```

## 5. 验收

固定 8×8、随机预算分配和 BO 预算分配使用相同 64 张图总预算、相同 PCPO 更新次数、seed 和验证集。日志必须记录每轮 8 个 image count，且总和为 64。
