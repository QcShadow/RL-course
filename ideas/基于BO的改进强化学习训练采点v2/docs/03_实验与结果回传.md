# 实验与结果回传

本包只要求完成“基于BO的改进强化学习训练采点v2”。主结论来自独立测试集，训练曲线用于了解选择行为。其它方法属于后续可选对照。

## 首轮建议

11 月 25 日的旧报告采用其他选点目标，不能作为 v2 结果。v2 必须使用新的独立运行目录。

先跑 v2 的 seed42、250 轮。起点、前 20 轮随机预热、图像生成设置和每轮预算固定；第 21 轮起按预测组内 reward 方差高优先选点，采集函数使用 UCB。

v2 前 20 轮从未训练文本中随机抽取，之后仍排除全部历史文本。250 轮训练 2,000 条不同文本。

如果做多个 seed，提前确定 seed 列表，例如 42、43、44，并在两个方法中使用相同列表。每个 seed 独立从同一起点训练。正式结果汇报每 seed 分数、均值、样本标准差、置信区间和样本数；只有一个 seed 时只报告单次结果，不宣称统计显著。

## 固定条件

| 条件 | 保持一致的内容 |
|---|---|
| 模型 | 同基础模型 revision、LoRA 初始化、训练精度 |
| 任务 | 同 OCR 数据集、同 PaddleOCR 资源与评分实现 |
| 训练 | 同 PCPO 损失、优化器、学习率、更新次数与采样参数 |
| 预算 | 250 轮，每轮 64 张训练图，预热计入总预算 |
| 测试 | 同 1,018 条独立提示、同评测采样配置与 seed、同 EMA 加载方式 |

未来记录到的新测试结果不回传给 selector。不要在测试集上找更好特征、调 UCB 系数或挑核之后，还把这批测试结果当作独立验证。

## 要看哪些指标

主指标是最终独立测试集的平均 OCR reward；如果原工程有严格文字准确率，也照同一实现记录。对比中间 epoch0/50/100/150/200/250 的测试曲线，可以判断提升速度。

同时记录训练轮均值、每提示组内 reward 方差、被选提示索引、优化器成功/跳过次数和总耗时。v2 直接优化组内 reward 方差，不能用训练方差升高证明模型变好；主结论看独立测试集。若 reward 基本只有 0 和 1，方差与均值存在直接关系，应增加“根据预热数据选中等难度提示”这一简单启发式对照，判断 GP 是否超过该基线。v2 生图预算为 16,000 张图，并记录 CPU 选点耗时。

检查每轮新增 8 条不同提示文本，已训练文本不能再次出现。断点恢复继续使用全部历史排除，不能只排除 GP 最近 50 轮见过的提示。事件日志中的 `selection_objective` 应与实验设置匹配。

## 每个运行交回什么

1. 原 `config.json`、最终 `summary.json` 和 `TRAINING_DONE.json`。
2. 完整 `events.jsonl`，其中同时包含 `bo_round` 和原训练指标。
3. 全部 `bo_state/` 与至少最终对应的模型检查点；恢复问题需要两者匹配。
4. 各 epoch 的逐条独立评测记录及测试配置。
5. 启动命令、实际 Python 依赖版本、GPU 型号、seed、方法名、墙钟耗时；失败时保留 stderr 和最近完整 checkpoint。

不要只发最终 LoRA 或一张平均分截图。我们需要逐提示分数与选择顺序，才能核对是否存在重复，以及 BO 选择的提示是否带来独立测试收益。

## 已知实验边界

v2 预测即时 PCPO 组内 reward 方差，并将其作为组内学习信号幅度的代理。它不等于更新收益或独立测试提升。整次训练覆盖 2,000 条不同提示由不重复规则保证，不能归因于 BO。优势裁剪、图片梯度抵消和模型随训练变化都会影响实际学习效果；须以相同预算的独立测试表现评价。
