# PCPO 的 BO 提示采样交付包

这个包提供两种基于贝叶斯优化的 PCPO 提示采样目标。v1 优先选择预测平均 OCR 得分较低的提示；“基于BO的改进强化学习训练采点v2”优先选择预测组内 OCR reward 方差较大的提示。PCPO 的生成、奖励、优势和参数更新仍使用原实现。

**先读本页，再按 [接入步骤](docs/01_接入步骤.md) 操作。** 已提供训练入口；GPU 训练尚未运行，CPU 接口验证结果见 [验证记录](docs/04_验证记录.md)。

## 两种 BO 目标

组件提供两种可公平对照的选点目标。v1 预测每条提示的平均 OCR reward，并优先挑较低分；v2 名称为“基于BO的改进强化学习训练采点v2”，预测同一提示 8 张图的 OCR reward 方差，并优先挑方差较大的未训练提示。两种方法都使用 UCB 或 logEI，PCPO 的原始奖励、优势和参数更新保持不变。

本交付中的 OCR 配置用每条提示内部的奖励差计算优势，并用整批奖励的标准差作分母。因此组内 reward 方差越大，该组优势的平方幅度越大。全 0 或全相同的组方差为 0，不能提供组内区分信号。v2 用这个可观测量作为 PCPO 学习信号强弱的代理；它不等于最终测试提升。

v2 的标签是每提示 8 个原始 reward 的总体方差：`mean((r - mean(r)) ** 2)`。这与 GP 的预测不确定性不同。GP 学提示特征到实测组内方差的关系；UCB 对预测方差标签取“预测均值 + 2 × 后验标准差”，再挑最高分。

## 每轮训练做什么

每轮选 8 条提示，每条生成 8 张图，总共 64 张图。前 20 轮随机抽取，收集初始数据。从第 21 轮开始，使用最近 50 轮的逐提示观测拟合高斯过程（GP）。v1 拟合平均 reward，v2 拟合组内 reward 方差。两者默认根据 UCB 取最高的 8 条不同且未训练提示，也可切换为 logEI。

这里的“采集函数”是给候选提示排优先级的公式。v1 的 UCB 使用 `−预测平均 reward + 2 × 后验标准差`，logEI 寻找比近期最低实测 reward 更低的提示。v2 的 UCB 使用 `预测组内 reward 方差 + 2 × 该预测的后验标准差`，logEI 寻找高于近期最高实测组内方差的提示。v2 的后验标准差表示 GP 对提示方差预测的不确定性，不是 8 张生成图之间的 reward 方差。

**一条训练观测是“一条提示，以及它生成的 8 张图的奖励统计”。** 每轮会新增 8 条观测。日志保留每组的原始平均 reward 和总体方差，v1/v2 各自选择需要的标签。64 张图的总平均分也保存，但只用于训练曲线。接口会拒绝用一个整轮总均值代替 8 条提示各自的标签。

```text
全部训练提示 → 特征编码（只需初始化一次）
                        ↓
随机预热 / GP + UCB 或 logEI → 选8条提示
                        ↓
原PCPO生成64张图 → 原OCR逐图评分
                        ↓
按数据集行号归组 → 每提示平均分与组内方差 → 下一轮GP
                        ↓
原PCPO优势计算和参数更新 → 保存同轮次检查点
```

## 固定设置

| 项目 | 本包设置 |
|---|---|
| 训练数据 | 随包提供原训练提示 19,653 行，按原数据集规则读取 |
| 特征 | 固定的 1530 维提示表示 |
| 核 | Matérn-5/2，共享一个长度尺度，核先验和原设计一致 |
| 特征参数 | 固定；训练中不重新设计 |
| GP 参数 | 每轮用近期真实观测重新拟合 |
| 默认采集函数 | UCB，标准差系数 2.0 |
| 可选采集函数 | logEI；random 用于同接口对照 |
| 预热 | 20 轮，包含在原 250 轮预算内 |
| 拟合窗口 | 最近 50 轮，最多 400 条观测；全部历史仍保存 |
| 每轮预算 | 8 提示 × 8 图；250 轮共 16,000 张训练图 |
| 重复提示 | 整次训练不重复文本；预热、BO、random 对照均排除全部已训练提示 |
| 运行范围 | 给定复现代码的 OCR 单 GPU 训练；多进程会明确报错 |

这次采用“每轮按单点采集分数取前 8 条”的批量策略，不是联合 qUCB/qEI，也没有批内幻想更新。预热后仍由 BO 选择全部 8 条；特征、核、窗口和生成预算沿用原设置。250 轮会使用 2,000 条不同提示文本；19,653 行候选中有 19,649 条不同文本，足够完成预算。排除名单来自全部历史，不受最近 50 轮拟合窗口限制。

## 最快检查包是否能运行

在**测试用的 Python 环境**中，从交付包根目录执行：

```bash
python -m pip install -r requirements.txt
PYTHONPATH=. python -B -m unittest discover -s tests -v
PYTHONPATH=. python -B examples/cpu_smoke.py --acquisition ucb --objective max_group_variance
PYTHONPATH=. python -B examples/cpu_smoke.py --acquisition logei --objective max_group_variance
```

运行前先确认依赖不会替换掉你原来可工作的 CUDA PyTorch。建议复制原训练环境后安装；实际测试环境及版本见验证记录。本地测试通过不等于服务器扩散模型能直接启动，正式跑前按接入文档做小规模 GPU 试跑。

## 设计与实验应怎样描述

v2 名称使用“基于BO的改进强化学习训练采点v2”。它让 BO 预测提示产生 PCPO 组内奖励差异的能力，用来分配训练提示；它没有改变 PCPO 优势公式、截断损失或优化器。奖励方差是学习信号强弱的代理，不是实际参数更新收益。GPU 实验需要与 random、v1 和中等难度选择基线比较。

最终看相同测试集、相同生成预算下的 OCR reward。修正版会主动选择难提示，训练均值下降也可能只是选择分布变了；是否有效要看独立测试集平均分是否提高。原 1,018 条测试提示和逐条测试得分都不进入 BO。实验如何比较见 [实验与结果回传](docs/03_实验与结果回传.md)。
