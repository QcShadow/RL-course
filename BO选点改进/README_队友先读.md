# PCPO 的 BO 提示采样交付包

这个包把 PCPO 训练中的随机抽提示，改为优先选择预测 OCR 得分较低、或预测不确定性较高的提示。生成模型、OCR 奖励计算和 PCPO 参数更新仍使用你已经跑通的代码。BO 在 CPU 上运行，生图和训练继续使用原 GPU。

**先读本页，再按 [接入步骤](docs/01_接入步骤.md) 操作。** 已提供改好的训练入口，通常不需要自己重写选点逻辑。2026-11-25 修正了原先偏向高 reward 的选点方向；修正版 RL 训练尚未运行，CPU 接口验证结果见 [验证记录](docs/04_验证记录.md)。

## 这一版实际做什么

每轮选 8 条提示，每条生成 8 张图，总共 64 张图。前 20 轮随机抽取，收集初始数据。从第 21 轮开始，使用最近 50 轮的逐提示平均奖励拟合高斯过程（GP），从整次运行尚未训练过的提示中，根据 UCB 分数取最高的 8 条不同提示。也可以把采集函数切换为 logEI。

这里的“采集函数”就是给候选提示排优先级的公式。默认 UCB 使用 `score = −预测平均 OCR reward + 2 × 预测标准差`，取分数最高的 8 条。logEI 寻找比近期最低实测 reward 更低的提示。两个策略都最小化提示的平均 OCR reward，让得分低的提示获得更高训练优先级。实现时仅在 GP 拟合前把 reward 取负，原始日志和 PCPO 训练奖励保持原值。

**一条训练观测是“一条提示，以及它生成的 8 张图的平均分”。** 每轮会新增 8 条观测。64 张图的总平均分也保存，但只用于画训练曲线。接口会拒绝用一个整轮总均值代替 8 条提示各自的标签。

```text
全部训练提示 → 特征编码（只需初始化一次）
                        ↓
随机预热 / GP + UCB 或 logEI → 选8条提示
                        ↓
原PCPO生成64张图 → 原OCR逐图评分
                        ↓
按数据集行号归组 → 每提示平均分 → 下一轮GP
                        ↓
原PCPO优势计算和参数更新 → 保存同轮次检查点
```

## 固定设置

| 项目 | 本包设置 |
|---|---|
| 训练数据 | 随包提供原训练提示 19,653 行，按原数据集规则读取 |
| 特征 | 固定的 1530 维提示表示 |
| 核 | Matérn-5/2，共享一个长度尺度，核先验和原设计一致 |
| 特征参数 | 固定；训练中不重新设计 |
| GP 参数 | 每轮用近期真实观测重新拟合 |
| 默认采集函数 | UCB，标准差系数 2.0 |
| 可选采集函数 | logEI；random 用于同接口对照 |
| 预热 | 20 轮，包含在原 250 轮预算内 |
| 拟合窗口 | 最近 50 轮，最多 400 条观测；全部历史仍保存 |
| 每轮预算 | 8 提示 × 8 图；250 轮共 16,000 张训练图 |
| 重复提示 | 整次训练不重复文本；预热、BO、random 对照均排除全部已训练提示 |
| 运行范围 | 给定复现代码的 OCR 单 GPU 训练；多进程会明确报错 |

这次采用“每轮按单点采集分数取前 8 条”的批量策略，不是联合 qUCB/qEI，也没有批内幻想更新。预热后仍由 BO 选择全部 8 条；特征、核、窗口和生成预算沿用原设置。250 轮会使用 2,000 条不同提示文本；19,653 行候选中有 19,649 条不同文本，足够完成预算。排除名单来自全部历史，不受最近 50 轮拟合窗口限制。

## 文件导航

| 路径 | 用途 |
|---|---|
| `pcpo_bo/` | 可复制进训练工程的独立 Python 模块 |

| `docs/` | 接入步骤、接口解释、实验流程和验证记录 |

## 最快检查包是否能运行

在**测试用的 Python 环境**中，从交付包根目录执行：

```bash
python -m pip install -r requirements.txt
PYTHONPATH=. python -B -m unittest discover -s tests -v
PYTHONPATH=. python -B examples/cpu_smoke.py --acquisition ucb
PYTHONPATH=. python -B examples/cpu_smoke.py --acquisition logei
```

运行前先确认依赖不会替换掉你原来可工作的 CUDA PyTorch。建议复制原训练环境后安装；实际测试环境及版本见验证记录。本地测试通过不等于服务器扩散模型能直接启动，正式跑前按接入文档做小规模 GPU 试跑。

## 设计与实验应怎样描述

方法名称可以写“贝叶斯主动采样 PCPO”。这次 BO 参与训练数据的分配，不调整学习率。已有完整 250 轮历史总均值只作为背景资料；正式 BO 启动时没有伪造逐提示标签，观测从新训练的预热阶段开始收集。

最终看相同测试集、相同生成预算下的 OCR reward。修正版会主动选择难提示，训练均值下降也可能只是选择分布变了；是否有效要看独立测试集平均分是否提高。原 1,018 条测试提示和逐条测试得分都不进入 BO。实验如何比较见 [实验与结果回传](docs/03_实验与结果回传.md)。
