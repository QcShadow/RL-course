## 已通过的 13 项测试

命令：`PYTHONPATH=. python -B -m unittest discover -s tests -v`。

| 测试 | 验证内容 |
|---|---|
| 打乱后的 reward 归组 | 64 张图乱序后，按数据集行号还原 8 个准确的均值 |
| 错误 reward 输入 | 整轮单个均值、每组图数不对时明确拒绝，pending 保留 |
| pending 与随机恢复 | 保存后恢复同一批提示，后续随机选择一致；拒绝变序候选池 |
| 全程不重复 | random/UCB/logEI 均排除历史文本及重复行；历史滑出窗口、保存恢复后仍排除；耗尽时明确报错 |
| 剩余池不足 | 只剩 2 条未训练提示时拒绝组建 8 条批次，不重用旧提示 |
| 原随机 sampler 首轮对齐 | 首轮相同 seed 下，原随机索引与 64 张图的打乱顺序一致；后续按新规则排除历史提示 |
| GP 与采集函数 | GP 拟合后 RL 的 Python、NumPy、Torch CPU RNG 和线程数恢复；分块 UCB/logEI 对照公式通过 |
| 低 reward 优先 | 相同不确定性下 UCB/logEI 均优先低分候选；GP 目标取负、logEI 阈值取负最低值，历史保留原始分数 |
| v2 方差优先 | 相同不确定性下 UCB/logEI 均优先预测组内方差较大的候选；GP 直接拟合总体方差，logEI 阈值使用近期最高方差，并保持 PCPO reward 未取反 |
| 旧状态隔离 | 拒绝续跑旧版最大化 reward 或允许跨轮重复的 BO 状态，要求另开运行 |
| v1/v2 状态隔离 | 恢复状态时拒绝切换目标，避免在训练中途改变 GP 标签含义 |
| 近期窗口 | 拟合只消费指定近期轮次，历史保留；预热按已完成轮次判断 |
| DataLoader 与检查点 | 实际 DataLoader 输出行号与标签归组正确，按 PCPO epoch 恢复；缺少匹配状态时拒绝 |

logEI 与 BoTorch 原生 `LogExpectedImprovement` 的对照使用 `rtol=1e-6, atol=1e-5`。块矩阵后验和 q=1 批量后验存在浮点差异，logEI 在远尾部会放大这些微小差异；测试核对的是数值实现一致性。

## 完整候选池检查

```bash
PYTHONPATH=. python -B examples/cpu_smoke.py --pool data/train.txt --warmup-rounds 50 --acquisition ucb --objective max_group_variance
PYTHONPATH=. python -B examples/cpu_smoke.py --pool data/train.txt --warmup-rounds 50 --acquisition logei --objective max_group_variance
```

这里为覆盖上限，把测试用预热设为 50 轮：随机生成 400 条图像 reward，按提示计算组内总体方差，然后执行一次真实 GP 拟合及全池选点，再做状态保存/加载。正式设置仍为预热 20 轮，不受测试参数影响。

| 方法 | 池大小 | 用于拟合的合成观测 | 本机单次测得耗时 |
|---|---:|---:|---:|
| UCB，v2 目标 | 19,653 | 400 | 6.92 秒 |
| logEI，v2 目标 | 19,653 | 400 | 6.94 秒 |

耗时为 2026-11-27 单次实测，两项检查并行执行。计时从 selector 初始化后开始，覆盖合成轮循环及状态保存/恢复，不含特征编码和生图/训练；不是多次性能基准。合成 reward 由固定随机数生成器产生，不能用于判断优化收益。每组只有 8 张图，方差标签也有抽样噪声。
