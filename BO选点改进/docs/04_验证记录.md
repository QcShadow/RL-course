依赖文件允许保留满足版本范围的 CUDA PyTorch，固定 BoTorch 与 GPyTorch 版本以保持 logEI 数值实现。服务器已有训练环境需单独验证，不能仅根据本机结果宣称兼容。

## 已通过的 8 项测试

命令：`PYTHONPATH=. python -B -m unittest discover -s tests -v`。

| 测试 | 验证内容 |
|---|---|
| 打乱后的 reward 归组 | 64 张图乱序后，按数据集行号还原 8 个准确的均值 |
| 错误 reward 输入 | 整轮单个均值、每组图数不对时明确拒绝，pending 保留 |
| pending 与随机恢复 | 保存后恢复同一批提示，后续随机选择一致；拒绝变序候选池 |
| 跨轮重复 | 允许重复训练提示，同一轮不出现相同文本 |
| 原随机 sampler 对齐 | 相同 seed 下，原随机索引与 64 张图的打乱顺序一致 |
| GP 与采集函数 | GP 拟合后 RL 的 Python、NumPy、Torch CPU RNG 和线程数恢复；分块 UCB/logEI 对照公式通过 |
| 近期窗口 | 拟合只消费指定近期轮次，历史保留；预热按已完成轮次判断 |
| DataLoader 与检查点 | 实际 DataLoader 输出行号与标签归组正确，按 PCPO epoch 恢复；缺少匹配状态时拒绝 |

logEI 与 BoTorch 原生 `LogExpectedImprovement` 的对照使用 `rtol=1e-6, atol=1e-5`。块矩阵后验和 q=1 批量后验存在浮点差异，logEI 在远尾部会放大这些微小差异；测试核对的是数值实现一致性。

## 完整候选池检查

```bash
PYTHONPATH=. python -B examples/cpu_smoke.py --pool data/train.txt --warmup-rounds 50 --acquisition ucb
PYTHONPATH=. python -B examples/cpu_smoke.py --pool data/train.txt --warmup-rounds 50 --acquisition logei
```

这里为覆盖上限，把测试用预热设为 50 轮：随机生成 400 条提示均值观测，然后执行一次真实 GP 拟合及全池选点，再做状态保存/加载。正式设置仍为预热 20 轮，不受测试参数影响。

| 方法 | 池大小 | 用于拟合的合成观测 | 本机单次测得耗时 |
|---|---:|---:|---:|
| UCB | 19,653 | 400 | 7.88 秒 |
| logEI | 19,653 | 400 | 11.06 秒 |

耗时覆盖脚本从 selector 初始化完成后开始的合成轮循环及状态保存/恢复，不含最初的特征编码，也不含生图/训练；这不是多次性能基准。合成 reward 由固定随机数生成器产生，不能用于判断优化收益。
