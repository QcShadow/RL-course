# 把交付包接入已跑通的 PCPO 工程

本包提供现成入口和底层接口。优先用现成入口；如果服务器代码已经改过，再按照末尾的手动接入位置合并差异。

## 1. 确认原工程

现成入口对应队友提供的 `PCPO_复现资料包(1)/04_代码与配置/本次复现驱动/source/train_sd3_PCPO_paper.py`，依赖原工程的 `paper_runtime.py`、`baseline_runtime.py`、`paper_config.py`、FlowGRPO 源码、OCR 模型与预计算 embedding。它不是官方仓库任意版本的通用补丁。

原训练集使用 `PrecomputedEmbeddingDataset`：去掉首尾空白并过滤空行后，第 i 行提示对应 HDF5 的第 i 个样本。**不要重新排序、去重或删行。** 包内 4 条重复文本保留；采样器会在整次运行中排除已经训练过的文本，包括相同文本的其他行，原始行号仍保持不变。

服务器需要已有基础模型 SD3.5-M、PaddleOCR 和训练/测试 HDF5；本包无需最终 LoRA 权重，也不提供这些大型文件。比较新方法时从原基座和相同 LoRA 初始化开始，不默认从最终训练权重开始。

## 2. 放置文件和依赖

以下 `delivery_dir` 换成服务器上解压后的真实目录。`project_dir` 换成原复现工程路径。运行命令前进入已经准备好的测试训练环境。

```bash
delivery_dir=/path/to/PCPO_BO交付包_20261123
project_dir=/path/to/pcpo-baseline

cp -R "$delivery_dir/pcpo_bo" "$project_dir/source/pcpo_bo"
cp "$delivery_dir/integration/train_sd3_PCPO_bo.py" "$project_dir/source/"
cp "$delivery_dir/integration/bo_rank_start.py" "$project_dir/source/"
cp "$delivery_dir/integration/bo_launch.py" "$project_dir/source/"
cp "$delivery_dir/integration/run_bo_task.sh" "$project_dir/jobs/"
python -m pip install -r "$delivery_dir/requirements.txt"
```

这里是第一次安装。如果目标已经有 `pcpo_bo/`，先把旧版改名留存再复制，避免目录嵌套。无需覆盖原 `train_sd3_PCPO_paper.py`、`paper_launch.py` 或 `paper_rank_start.py`。

新脚本实际调用关系是：

```text
run_bo_task.sh → bo_launch.py → bo_rank_start.py → train_sd3_PCPO_bo.py
```

只复制训练文件但还调用原 `paper_launch.py` 会继续跑普通 PCPO。原 launch 层最后会重新加载 EMA 做独立评测；新 launch 保留了这个行为。

`run_bo_task.sh` 中的原服务器路径（`PCPO_PROJECT`、`PCPO_DATA2`、`PCPO_ENV_PREFIX`）来自队友脚本。如服务器位置不同，先改这三处。还需要原环境的 Slurm 作业变量和 GPU 分配；不要把 macOS 的本地测试命令当 GPU 提交脚本。

## 3. 先做 CPU 检查

在解压目录执行 README 中的单元测试和两个 CPU 示例。也可以在全部训练提示上验证选点：

```bash
PYTHONPATH=. python -B examples/cpu_smoke.py --pool data/train.txt --acquisition ucb
```

示例会随机制造 reward 来检查软件流程，不能当作项目实验结果。它不写任何可被正式入口加载的训练状态。

## 4. 提交随机对照与 BO 实验

沿用队友已有的 Slurm 资源申请与 GPU UUID 分配。在原 job 中调用任务脚本的位置，改为如下形式；`gpu_uuid` 使用原 job 已经分配的变量。每次调用只给一张卡。

```bash
project_dir=/path/to/pcpo-baseline
export PCPO_RUN_ROOT=/path/to/new_runs/bo_min_ucb_seed42
export PCPO_BO_ACQUISITION=ucb
export PCPO_TARGET_EPOCHS=250
bash "$project_dir/jobs/run_bo_task.sh" ocr "$gpu_uuid" 1
```

实际结果在 `$PCPO_RUN_ROOT/ocr-seed42`，必须给每个方法使用独立的新目录。2026-11-25 修正版最小化选点 reward，并禁止跨轮重复训练相同提示；不要复用旧版高 reward 优先或允许跨轮重复实验的目录与 BO 状态。接口仍接收原始 [0,1] OCR reward，调用方不要取负。随机对照也从未训练过的提示中选，使用同一套排除规则。启动时只改：

```bash
export PCPO_RUN_ROOT=/path/to/new_runs/random_seed42
export PCPO_BO_ACQUISITION=random
```

logEI 对照只改为新的结果目录和 `PCPO_BO_ACQUISITION=logei`。现成补丁沿用原始 seed42；做多个 seed 时，把原配置的生成/训练 seed 和补丁中 `bo_options.seed`、`SelectedPromptBatchSampler.seed` 一起设为该实验预先指定的 seed，并使用独立目录。不要中途改变已有运行的设置。

**首次 GPU 检查先开独立试跑目录，至少跑 21 轮**，这样才能跨过 20 轮预热并实际执行一次 BO。设 `PCPO_TARGET_EPOCHS=21` 即可；试跑目录只用于检查，正式 250 轮另开目录并恢复目标值。只跑 2 轮只能检验随机预热与归组，不能证明 BO 路径跑过。

## 5. 运行中核对什么

`events.jsonl` 中新增 `event="bo_round"`：

- `epoch` 从 0 开始；0–19 为随机，20 起为 ucb 或 logei。random 对照全程随机。
- `prompt_indices` 长度为 8，对应数据集原始行号；`selection_objective` 为 `minimize_prompt_mean_ocr_reward`，表示 BO 目标，随机阶段仍均匀抽样。
- `image_rewards` 形状为 8×8；`prompt_mean_rewards` 长度为 8。
- `round_mean_reward` 应等于这 8 个提示均值的平均，也应与原 `reward_ocr` 一致，允许浮点精度差异。
- 原 `sampling_budget` 应继续是 64 张图、8 条不同提示、每提示 8 张图。完成 n 轮后应累计使用 8n 条不同文本；不足 8 条未训练文本时会明确报错，不回收旧提示。

接口抛错时直接看报错和原始数据。本版不会把 GP 拟合失败悄悄改为随机采样。UCB 得分可以大于 1，logEI 得分通常为负，这不是 OCR reward 超界；输入的真实 OCR reward 才必须在 [0,1]。

## 6. 中断与恢复

状态版本为 `pcpo-prompt-bo-v3-min-reward-no-repeat`，加载旧版最大化 reward 或允许跨轮重复的状态会报错，请另开目录重新训练。

新增 `bo_state/epoch-000020.json` 表示已经完成 20 轮、下一轮 epoch=20。它保存全部历史、设置和候选池顺序摘要；如果已选好下一轮但尚未结束，还会保存 pending 的提示索引。

继续使用原 PCPO 恢复机制加载模型检查点。训练入口读到恢复后的 epoch，自动加载**同 epoch** 的 BO 文件，并检查设置与候选池是否一致。不要只复制“最新 BO 文件”，也不要把新模型配旧 BO 文件。

保存顺序是：PCPO 更新完成 → 保存对应下一 epoch 的 BO 文件 → 原 runtime 保存模型检查点。两者不是一个原子文件；如果在这之间崩溃，可能多出一个更晚的 BO 文件。恢复时按实际模型 epoch 读取，自动忽略多出的文件。

若旧普通 PCPO 检查点没有对应 BO 状态，本版会报错。旧日志无法还原逐提示 Y，因此不能直接从旧训练 epoch20 接着做 BO。应启动带本模块的新预热，或另行准备真正匹配的观测与模型状态。

## 7. 手动合并时的六个位置

详细差异在 `integration/pcpo_bo.patch`；完整修改版在同目录。

1. 把 `KRepeatSampler` 换为 `SelectedPromptBatchSampler`，传入数据集大小、微批大小和原来每提示图数。
2. 在 `baseline_runtime.initialize(...)` 返回 epoch 之后，调用 `load_for_epoch(...)`。第一次从 epoch0 创建新 selector。
3. 在每轮创建 `DataLoader` 迭代器之前调用 `next_batch()`，把 8 个索引交给 sampler。每次重复请求会返回同一个 pending batch。
4. 生图时把 `batch['indices']` 与图片奖励一起放进 `samples`。不要使用 tokenizer 的 token IDs，也不要重新解码 prompt 作为行号。
5. 奖励收集后，在删奖励或计算训练批次之前，调用 `observe_flat(indices, gathered_rewards['ocr'])`。额外的行号张量随后 `pop` 掉，不进入 PCPO loss。
6. 原参数更新完成、`epoch += 1` 之后，把 BO 状态保存到同 epoch 的文件，然后调用原 `end_epoch`。

现成适配明确只支持一个进程。若以后要多 GPU，需要 rank0 统一选点并广播，所有 rank 用相同顺序拼接全局行号与奖励，rank0 只提交一次全局观测；不能在每张卡独立选 8 条后还沿用全局 64 图预算。
