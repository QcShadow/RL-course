# 接口与方法说明

队友只需要理解三个操作：初始化提示池、申请下一轮 8 条提示、交回对应图像得分。特征编码、GP 拟合、候选评分由组件完成。

## 1. GP 在这里学什么

把提示文字变成数字向量称为“特征编码”。GP 是一个根据已观测样本预测新样本分数、同时给出不确定性的模型。核函数告诉 GP 两条提示有多相似。

以 v1 为例，本轮选中提示 A–H，各生成 8 张图。提示 A 的分数是 `[1, 1, 0, 0, 1, 1, 0, 0]`，原始均值是 0.5。接口和日志保留这个均值，GP 内部拟合 −0.5，使最大化采集函数优先选择低 reward 提示。v2 在同一组分数上拟合总体方差 0.25。

形式上：`Y_t(x) = (r_1 + ... + r_8) / 8`。每轮 8 个 Y，共 64 个原始分数。旧资料包中每轮只有一个全局平均数，不能作为这里的 8 个标签。

模型训练后，提示的潜在得分会变化，所以每轮重新拟合、只用最近 50 轮观测。v1 的 Y 是每提示平均 reward；v2 的 Y 是同组 8 张图 reward 的总体方差。已训练提示在本次运行中不再被选择；GP 用历史标签预测尚未训练提示的目标值。这是对变化过程的简单处理，不是时间核。时间和模型步数只用于记录，不偷偷加进冻结的 1530 维表示。

## 2. 初始化

```python
from pcpo_bo import PromptBOSelector

# 必须保持与 HDF5 / 训练 Dataset 完全相同的行序。
rows = [{"prompt": text} for text in train_dataset.prompts]
selector = PromptBOSelector(
    rows,
    seed=42,
    acquisition="ucb",  # ucb、logei 或 random
    objective="min_reward",  # min_reward 或 max_group_variance
    beta=2.0,
    warmup_rounds=20,
    batch_size=8,
    images_per_prompt=8,
    window_rounds=50,
)
```

这段放在一次训练运行初始化处，不要每轮创建新的 selector。初始化会把完整候选池编码为 CPU float64 特征矩阵。19,653×1530 的矩阵本身约 229 MiB，另有 GP 与 Python 内存开销。组件不下载模型、不访问 LLM，也不需要 GPU。

| 参数 | 含义 |
|---|---|
| `seed` | 提示采样与 GP 拟合的可复现种子；在记录中保留 |
| `acquisition` | `ucb` 默认；`logei` 备选；`random` 全程随机对照 |
| `objective` | `min_reward` 为 v1；`max_group_variance` 为 v2 |
| `beta` | 本实现中乘在标准差上的系数，不是有些库里的平方系数 |
| `warmup_rounds` | 开始时随机收集多少轮，正式推荐为 20 |
| `batch_size` | 每轮提示数，当前实验为 8 |
| `images_per_prompt` | 每条提示生成图数，当前实验为 8 |
| `window_rounds` | GP 拟合取最近几轮，当前实验为 50 |

## 3. 申请下一轮提示

```python
indices = selector.next_batch()  # np.ndarray，形状 (8,)，数据集原始行号
selected_texts = [rows[int(i)]["prompt"] for i in indices]
```

每次给出的索引都在训练池内。预热、BO 和 random 对照均排除全部历史中已训练过的文本；同轮和跨轮都不重复。相同文本的其他行也排除，检查点恢复后继续遵守此规则。排序分数相同则按原行号打破平局。观察提交前再次调用，会返回同一组待完成的索引，不会再采一次。剩余不同文本不足 8 条时直接报错，不凑小批次，也不重用旧提示。

BO 轮使用最近窗口拟合一个 `SingleTaskGP`。v1 将原始平均 reward 取负后拟合，后验输出处于负 reward 单位。v2 直接拟合每组 8 个 reward 的总体方差，后验输出处于方差单位。两者都在 GP 内部标准化 Y；特征不另做标准化，以免改变既定距离尺度。

v1 的 UCB 等价于 `−预测平均 reward + beta × 后验标准差`；logEI 的 `best_f` 是 `-min(窗口内平均 reward)`。v2 的 UCB 是 `预测组内 reward 方差 + beta × 后验标准差`；logEI 的 `best_f` 是窗口内最大的实测组内方差。后验标准差是不确定性 bonus，不等于图片间 reward 标准差。两种 logEI 均使用 BoTorch 0.18.1 的稳定 log-EI 数值公式。不确定性使用潜在函数后验，不包含额外观测噪声。

v2 与 PCPO 的联系来自优势定义。该 OCR 配置按每条提示减去组均值，再除以整批 reward 标准差。因而单组优势的均方幅度等于该组总体 reward 方差除以整批方差。v2 用前者的分子作为学习信号强弱代理，不声称它能预测最终泛化收益；优势裁剪和不同图片的梯度抵消也会影响实际更新。

候选池每 128 行分块计算后验，避免创建整个 19,653×19,653 协方差矩阵。过滤全部已训练文本后，按分数一次选前 8 条；没有选第一条后再做幻想标签、重拟合或联合优化。因此这 8 条可能相似，这属于本版已声明的批量策略。

## 4. 回填分数：两个接口选一个

### 分数已经按提示排成 8×8

```python
record = selector.observe_round(
    indices,
    image_rewards,  # shape=(8, 8)，第i行必须对应indices[i]
    policy_step=global_step,  # 生成这批图片时的训练步数
)
```

每一行是同一条提示的 8 张图，组件算行均值作为原始 Y。调用方传原始 OCR 分数，取负只在组件拟合 GP 时发生，PCPO 的奖励方向不变。

### PCPO 生成顺序已打乱

这是随包训练入口实际使用的接口：

```python
record = selector.observe_flat(
    dataset_indices,  # shape=(64,)，每张图对应的数据集行号
    ocr_rewards,      # shape=(64,)，按同一顺序排列的原始OCR分数
    policy_step=global_step,
)
```

组件按行号重新归组，检查每条提示恰好有 8 个 reward。它会拒绝少图、多图、错误行号和 NaN。不要传 tokenizer 的 token IDs，不要拿最后一个微批次的 `prompts` 去代表整轮，也不要 `reshape(8, 8)` 后假设同一提示相邻。

图像失败导致 OCR 得分为 0 的情况沿用原 reward 逻辑，仍保留该图的分数。若生图过程本身没有返回某张图，不要静默补 0；修复或恢复这一轮，让原训练预算与日志一致。

返回记录包含：

```json
{
  "epoch": 0,
  "selection_method": "random",
  "selection_objective": "random_without_replacement",
  "prompt_indices": [10, 20, 30, 40, 50, 60, 70, 80],
  "acquisition_scores": null,
  "policy_step": 0,
  "image_rewards": [[0.5, 0.5, 0.5, 0.5, 0.5, 0.5, 0.5, 0.5]],
  "prompt_mean_rewards": [0.5],
  "prompt_reward_variances": [0.0],
  "round_mean_reward": 0.5
}
```

上面只为说明字段，`image_rewards`、`prompt_mean_rewards` 和 `prompt_reward_variances` 省略了另外 7 条记录，不能直接作为接口输入。真实文件分别有 8 行和 8 个值。方差是每条提示 8 个原始 reward 的总体方差。`acquisition_scores` 在 BO 阶段是 8 个分数，与原始 reward 不同。

## 5. 检查点接口

```python
selector.save_state("bo_state/epoch-000020.json")
restored = PromptBOSelector.load_state("bo_state/epoch-000020.json", rows)
```

当前状态版本为 `pcpo-prompt-bo-v4-objectives-no-repeat`，保存目标、采集函数、全部历史和待处理索引；不同目标、旧版高 reward 最大化或允许跨轮重复的状态均不能混用。加载时重新编码相同池，下一次选点重新拟合。随机阶段按 `seed + completed_rounds` 使用独立 Torch generator，因此恢复不依赖训练进程的全局 RNG。GP 在隔离的 CPU 随机状态内运行，结束后恢复 Python、NumPy、Torch CPU RNG 与 Torch 线程数。

`load_for_epoch(rows, directory, epoch, **options)` 是训练入口使用的辅助函数。它核对恢复 epoch、采样设置与池摘要；缺少非零 epoch 的 BO 文件会报错，不会拿空历史接着跑。

## 6. 特征和核的组成

| 特征范围 | 内容 |
|---|---|
| 0–15 | 目标长度、词数、数字/标点占比、大小写与提示结构 |
| 16–53 | 目标文字归一化后的 38 类字符计数 |
| 54–1497 | 38×38 类相邻字符组合计数 |
| 1498–1529 | 引号外的载体、字体、光照、模糊、遮挡等词面线索 |

目标文字使用原评分器的第一对 ASCII 双引号提取规则，评分用的文字只去掉普通空格并转小写。特征还保留原文字的大小写与空格占比，因为它们可能影响生成。语境词组在引号外提取，避免把要求绘制的文字误当作场景指令。

核为共享长度尺度 Matérn-5/2，`nu=2.5, ard=False`，没有额外 ScaleKernel。核长度尺度采用对数正态先验，具体参数见 `pcpo_bo/kernel.py`。1530 维特征并不等于拟合 1530 个长度尺度；这一版只拟合一个共享长度尺度，另有 GP 均值和噪声参数。

`pcpo_bo/features.py` 与 `pcpo_bo/assets/feature_schema.json` 定义固定特征。采集函数可选 UCB 或 logEI；切换采集函数不会改变特征与核。

## 7. 代码职责

| 文件 | 职责 |
|---|---|
| `features.py` | 原样执行冻结特征编码 |
| `kernel.py` | 构造原样核结构、先验和约束 |
| `gp.py` | 保护 RL 随机状态，并拟合均值/核参数/噪声 |
| `acquisition.py` | 用后验为候选提示计算 UCB 或 logEI |
| `selector.py` | 预热、选点、reward 归组、历史窗口和持久化 |
| `pcpo_adapter.py` | 把选中索引重复成 64 张图，并对接恢复 epoch |

组件不会训练扩散模型。`next_batch()` 返回以后，接下来由原 PCPO 负责生图、算 reward、计算优势和更新 LoRA。
