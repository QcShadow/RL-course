# 实验与结果回传

先在同预算下比较随机抽样与 BO 抽样。主结论来自独立测试集，训练曲线用于了解选择行为。

## 首轮建议

先跑 random 与 UCB 各一个 seed42，总轮数均为 250。前 20 轮的提示选择方式、模型起点、图像生成配置和每轮预算相同；之后 random 继续随机，UCB 使用近期观测选 8 条提示。logEI 是下一项明确对照，不必一开始把很多超参数组合都跑一遍。

在相同输入、相同 seed 且未抽到重复文本的两行时，随机阶段的索引和 64 图打乱顺序与原 `KRepeatSampler` 一致；这一点有测试覆盖。由于原池有 4 行重复文本，本包在同一轮内会跳过重复文本的第二行，这条规则同样用于 random 对照。正式比较建议使用同一个新入口的 random 分支，而不是只与历史日志比较。

如果做多个 seed，提前确定 seed 列表，例如 42、43、44，并在两个方法中使用相同列表。每个 seed 独立从同一起点训练。正式结果汇报每 seed 分数、均值、样本标准差、置信区间和样本数；只有一个 seed 时只报告单次结果，不宣称统计显著。

## 固定条件

| 条件 | 保持一致的内容 |
|---|---|
| 模型 | 同基础模型 revision、LoRA 初始化、训练精度 |
| 任务 | 同 OCR 数据集、同 PaddleOCR 资源与评分实现 |
| 训练 | 同 PCPO 损失、优化器、学习率、更新次数与采样参数 |
| 预算 | 250 轮，每轮 64 张训练图，预热计入总预算 |
| 测试 | 同 1,018 条独立提示、同评测采样配置与 seed、同 EMA 加载方式 |

未来记录到的新测试结果不回传给 selector。不要在测试集上找更好特征、调 UCB 系数或挑核之后，还把这批测试结果当作独立验证。

## 要看哪些指标

主指标是最终独立测试集的平均 OCR reward；如果原工程有严格文字准确率，也照同一实现记录。对比中间 epoch0/50/100/150/200/250 的测试曲线，可以判断提升速度。

同时记录训练轮均值、被选中的提示索引、提示重复频次、每轮生图数、原优化器成功/跳过次数和总耗时。BO 可能偏好简单提示，因此训练 reward 增加不能单独证明模型更好。相同 16,000 张图预算的效果与额外 CPU 耗时应一起汇报。

预热后仍允许重复训练同一提示。反复选中同一批不是“候选池被删光”的错误，而可能是 UCB 当前的排名结果。先保留日志观察，不要在一个实验中临时改随机混合比例。后续要增加探索策略时另开明确的对照组。

## 每个运行交回什么

1. 原 `config.json`、最终 `summary.json` 和 `TRAINING_DONE.json`。
2. 完整 `events.jsonl`，其中同时包含 `bo_round` 和原训练指标。
3. 全部 `bo_state/` 与至少最终对应的模型检查点；恢复问题需要两者匹配。
4. 各 epoch 的逐条独立评测记录及测试配置。
5. 启动命令、实际 Python 依赖版本、GPU 型号、seed、方法名、墙钟耗时；失败时保留 stderr 和最近完整 checkpoint。

不要只发最终 LoRA 或一张平均分截图。我们需要逐提示分数与选择顺序，才能分辨 BO 是否一直选容易样本，以及收益是否体现在独立测试上。

## 已知实验边界

这版是“预测即时 OCR reward，并据此分配训练提示”。它实现了随机采样改为贝叶斯引导采样，但尚未证明能提升 PCPO 的最终泛化表现。固定最近 50 轮窗口和单点排序取前 8 条都是已确定的首版设置；方法如果没有收益，保留该结果再做下一版，不修改已完成运行的数据。
